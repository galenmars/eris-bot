Core Principles

GOLDEN RULE

Code flows down. Data flows up.

Unidirectional Dependency

A file may only import from layers below it. Cogs → Sequences → Domain → Math. Domain must never import from a Cog.

Pure Logic Principle

If a function doesn't touch Discord or a database, it lives in Domain or Math. This enables unit testing without mocking Discord.

Sequence-Driven Flows

Any operation spanning more than one interaction lives in Sequences. Never block the main bot thread in a Cog.

The JSON is the Config

Game balance lives in the theme JSON. To change a matchup bonus, edit the file — not the Python. The engine consumes config; it doesn't hardcode it.

// 03

Layer Responsibilities

LAYER 01
Cogs
cogs/

The remote control. Handles Discord slash commands, buttons, and events. Validates permissions, parses arguments, calls the appropriate Sequence.

⚠ Never write business logic here
LAYER 02
Sequences
sequences/

The project manager. Handles wait_for loops, DM conversations, timeouts, and orchestrating multiple domain and repo calls in sequence.

⚠ Only layer allowed to bridge user input + multi-step logic
LAYER 03
Domain
core/domain/

The rules of the game. Pure input/output functions — returns data or raises a DomainError. No side effects, no Discord objects, no SQL.

⚠ No discord.Member, no await, no DB calls
LAYER 04
Math
core/math/

The physics engine. Deep computation: dice rolls, matchup bonuses, loss tables, EMS calculations. Consumes theme.json as configuration.

⚠ These functions don't know the bot exists
LAYER 05
Data
core/data/

The database. SQL execution and data mapping via the Repository pattern. One file per domain (e.g. battle_repo.py). No business logic — only queries.

⚠ Raw SQL lives here and nowhere else
CROSS-CUTTING
Shared
core/shared/

Code that would otherwise be duplicated across three Cogs. Includes the faction/organization picker, embed formatters, and shared constants.

⚠ Never import from Cogs, Sequences, or Data
// 04

Request Lifecycle: /battle engage

1
cogs/battle_cog.py

Verifies interaction.user permissions and that the user has an enrolled commander. Calls battle_flow.engage().

2
sequences/battle_flow.py

Traffic controller. Handles the DM tactic-selection prompt, wait_for loop, and timeout. Asks Domain if the chosen tactic is legal.

3
core/domain/battle.py

"Is this tactic valid for this commander?" Returns True or raises DomainError. Knows nothing about Discord.

4
core/math/dice.py

Calculates the round total: reads tactic bonuses from theme.json, rolls dice, returns the result. Pure computation.

5
core/data/battle_repo.py

Saves the round result to SQLite. The Sequence drives when the commit happens — never a half-finished state.

6
core/shared/

Formats and posts the battle result embed to the channel. Display logic stays out of both the Sequence and the Cog.

Folder Manifest

Folder What lives here Why
cogs/ Slash commands, buttons, select menus Only what the user sees and clicks
sequences/ wait_for loops, DM flows, timeouts Any process spanning more than one interaction
core/domain/ Validation rules, eligibility checks Game logic that works identically in tests, DMs, or slash commands
core/math/ Formulas, dice, matchup table lookups Pure computation. Consumes theme.json as configuration
core/data/ SQL queries only — one file per domain The rest of the bot never writes raw SQL
core/shared/ Faction/org picker, embed builders, constants Code that would otherwise be copy-pasted across three Cogs
themes/ JSON theme files (factions, matchups, ship stats) Swap the entire game balance without touching Python
docs/ Fleet builder, army builder, architecture page Static GitHub Pages assets — no server required
// 06

Developer Rules

When a new developer joins the project, give them these four rules:

No Discord Objects in Domain / Math

Pass int IDs or plain dict records. Never discord.Member or discord.Interaction.

Unidirectional Imports Only

Cogs → Sequences → Domain → Math. If you're importing a Cog inside Domain, you've broken the architecture.

Repo Commits, Sequences Drive

The Data layer owns db.commit(). The Sequence layer decides when the commit happens — never save a half-finished state.

The JSON is the Config

Change game balance in theme.json, not in Python. The math engine reads config; it doesn't hardcode it.

// 07

Maintenance Checklist

Use this when reviewing any new file or PR. Click to mark complete.

Does the file contain Discord objects (Member, Interaction)?
→ Yes: file belongs in cogs/ or sequences/
→ No: should be in domain/, math/, or data/
Does the file use await?
→ Yes: likely part of Sequences or Cogs
→ No: should be a pure function in Domain or Math
Does the file write raw SQL?
→ Yes: must live in core/data/ — never in a Cog or Sequence
→ No: call a repo function from core/data/ instead
Does the logic span multiple interactions or DM steps?
→ Yes: it lives in sequences/ — not in the Cog
→ No: single-interaction logic is fine in the Cog
Is the same code duplicated in more than one Cog?
→ Yes: extract it to core/shared/
→ No: leave it where it is
// 08

Adding a New System

To add a Mercenary Contract System as an example — you create four new files and touch nothing existing:

# Step 1 — Persistence
core/data/mercenary_repo.py     ← SQL for the mercenary_contracts table

# Step 2 — Rules
core/domain/mercenary.py        ← can_sign_contract(), validate_contract_terms()

# Step 3 — Flow
sequences/mercenary_flow.py     ← DM negotiation conversation

# Step 4 — Interface
cogs/mercenary_cog.py           ← /contract sign slash command

# Optional — UI
core/shared/mercenary_embeds.py ← embed builders if needed

This is the architecture working as intended. New systems slot in without touching existing code.

The Organization System (Real Example)

The organization layer added in v2 followed exactly this pattern:

core/data/guild_repo.py         ← get_organizations(), add_organization(), remove_organization()
core/shared/faction_picker.py   ← merged theme factions + custom orgs in one picker
cogs/admin_cog.py               ← /admin org add · list · remove

No changes to Domain, Math, or any Sequence. Three files, zero regressions.
